How do I… (common tasks)

Add zip codes for a new area

Edit config/regions.yaml. Add zips under an existing region or define a new one:

South_Bay:
  - 90277  # Redondo Beach
  - 90501  # Torrance

Then use the Discovery card above with the region selected. --auto processes zips ordered by distance from HOME_ZIP=90045.

⚠ Each zip uses roughly $0.50 of Places API credit. --max-zips 2 is a safe default. Don't run a 100-zip region unattended.

Check for duplicate drafts in Zoho before sending

The daily draft scripts now run an audit preflight before uploading new initial or follow-up drafts. Use this read-only audit before a manual bulk send or whenever you want an independent check of what's already sitting in Zoho:

python scripts/audit_drafts.py

Scans Zoho Drafts (last 90 days), cross-references against Leads + Already_Contacted + Archive, and also flags duplicate drafts already waiting in Zoho. Reports flagged initials and flagged follow-ups separately.

Initial flagged = address was already used in a prior send. Delete in Zoho before sending.
Follow-up flagged = follow-up was already sent, lead is terminal (replied/bounced/closed), or another follow-up draft already exists. Delete in Zoho.

See which schools clicked the demo link

Run with optional filters:

python scripts/show_clicks.py
python scripts/show_clicks.py --since-days 7
python scripts/show_clicks.py --campaign followup
python scripts/show_clicks.py --campaign initial --since-days 30

Highlights "clicked but not replied" leads — prime second-follow-up candidates.

Mark a lead as do-not-contact

Three paths, fastest first:

  1. Grid DNC — /review bottom grid, click the red DNC button on any row. Confirms first.
  2. Top-card DNC — /review top card, click Mark do-not-contact.
  3. From search — /leads → search → click Edit ↑ → DNC button.

All three set status=do_not_contact with a reason stored in do_not_contact_reason.

Find a specific school

Search bar on /leads does case-insensitive "contains" across name, website, and email. Combine with status / zip / category filters if needed.

Click Edit ↑ on a row to open in /review. The Review page auto-picks the right mode (classify / owner / pre_send) based on the lead's current status.

Re-run downstream after editing leads in Review

If you edited leads in Review (classified or filled in owner), they're now ready_for_owner_lookup and need Phase 4 to advance them to ready_to_send.

An amber banner appears at the top of this page when this is needed. Click Run downstream in the Downstream card above to process them.

Age out stale leads + archive disqualified ones (weekly)

Always dry-run first — no --commit flag means read-only:

python scripts/run_close_stale.py
python scripts/run_cleanup.py

Inspect the output. If it looks right:

python scripts/run_close_stale.py --commit
python scripts/run_cleanup.py --commit

run_close_stale — marks sent leads with no reply ≥ 7 days post-follow-up as closed_no_reply. Use --days N to change the threshold.

run_cleanup — moves online_system_exclude, closed_no_reply, bounced, do_not_contact, already_contacted from Leads to Archive. Idempotent (dedupes by id). Rate-limited at 30 writes/min; 500+ row cleanups take 10–20 min.

⚠ Cleanup deletes rows from Leads. The Archive copy is the only record afterward.

Run the daily pipeline manually

Normally runs via GitHub Actions at 14:30 UTC Mon–Fri. To trigger now, click Run daily now in the Daily Run card above, or from terminal:

python scripts/run_daily.py

Order: sync (Phase 6) → audit-gated followup drafts (6b) → owners (Phase 4) → audit-gated initial drafts (Phase 5). Skippable steps:

python scripts/run_daily.py --skip-sync
python scripts/run_daily.py --skip-followup
python scripts/run_daily.py --skip-owners
python scripts/run_daily.py --skip-drafts

Sync sent + replies + bounces from Zoho only

python scripts/run_phase_6_sync.py
python scripts/run_phase_6_sync.py --dry-run
python scripts/run_phase_6_sync.py --since-days 60

Reads Sent (marks sent) and Inbox (marks replied / bounced). Default scan window is 30 days; bump with --since-days if you sent older messages outside the system.

Both threaded bounces (mailer-daemon with In-Reply-To) and unthreaded ones (standalone failure notices) are caught. Detects both 4xx and 5xx SMTP codes.

What do the Review tabs mean?

  • Classify — needs_enrollment_system_classification: Phase 3 couldn't decide. Pick enrollment_method (contact_form_qualify / email_qualify / pdf_form_qualify / third_party_form_qualify) or mark online_system_exclude.
  • Owner review — needs_owner_review: Phase 4 couldn't find owner/email. Fill in what you can.
  • Pre-send polish — ready_to_send leads with blank owner_name. Add a name so the draft uses it instead of "Hi there".

A school's email is bouncing — what happens?

Phase 6 sync auto-detects mailer-daemon notifications (both threaded replies and unthreaded ones from mailer-daemon@mx.zohomail.com) and flips the lead to bounced with the SMTP error code in do_not_contact_reason. You get a 📭 alert email per bounce.

Both 4xx (soft bounces that became permanent after retry) and 5xx codes are caught. Next run_cleanup.py --commit archives the row. No manual action needed.

Find duplicate Leads with strong duplicate evidence

The auto-check runs after every Phase 1. It only demotes strong duplicates such as same email, same address, same phone, or same exact non-root URL path. Similar names or shared root domains can be separate locations and stay eligible.

python -c "from src import dedupe_within_leads; print(dedupe_within_leads.dedupe_within_leads(dry_run=True))"

Reports checked, duplicates_found, rows_demoted. To actually demote them, drop dry_run=True:

python -c "from src import dedupe_within_leads; print(dedupe_within_leads.dedupe_within_leads())"
python scripts/run_cleanup.py --commit

Lower-priority true duplicates get flipped to do_not_contact with reason internal_duplicate:<kept_id>. The kept row is chosen by status priority (replied > sent > awaiting_approval > ready_to_send > …). Rows with different known emails are kept as separate outreach opportunities.

I'm getting low replies — should I rework the pitch?

Yes. As of 2026-07-06, outreach has reached 575 unique recipients, so low replies are signal, not noise.

Step 1: Confirm send volume.

python scripts/sent_email_count.py

The old threshold was 80–100 unique recipients. You are past it. Do not keep scaling the same message and pretend volume is still the blocker.

Step 2: Confirm deliverability isn't the problem.

  • mail-tester.com — visit the site, get a temp address (e.g. test-xxxxx@srv1.mail-tester.com), send a real outreach email to it from Zoho, click "Check your score." Anything below 9/10 means the score itself is the problem. 10/10 = deliverability clean.
  • Send to a personal Gmail account. Send a real outreach email to a Gmail address you own. Check whether it lands in Inbox, Promotions, or Spam. Spam = your sender reputation or content is being flagged.
  • MX Toolbox blacklist check — mxtoolbox.com/blacklists.aspx. Enter enrollifyapp.com and check Zoho's outbound IP 136.143.188.16. Anything on a major RBL (SpamCop, Spamhaus, Barracuda) needs to be cleared via Zoho support before sending more.
  • Verify DNS records still pass. Use mxtoolbox.com SPF / DKIM / DMARC checks against enrollifyapp.com. SPF must include zoho.com; DKIM record at zoho._domainkey must verify; DMARC should be at p=quarantine or stronger.

Step 3: After deliverability clears, change the experiment. Test offer, target segment, proof, CTA, and channel. Real-world follow-up with clickers is worth trying, but Brent and Carmen are no longer valid conversion evidence.
